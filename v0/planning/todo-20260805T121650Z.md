# Project review — 2026-08-05

Repository state at review time: branch `main`, clean working tree, `47570a7 chore(release): 1.31.0`.
Scope: 475 skills across 46 plugins, the website in `v0/www`, the validator and release scripts in
`v0/scripts`, and the two GitHub workflows.

Nothing in the repository was changed to produce this review.

## What's healthy

Every check the project already gates on passes:

| Check | Result |
| --- | --- |
| `npm run validate-skills` | 475 skills across 46 plugins, clean |
| `tsc --noEmit` (website) | clean |
| `eslint` (website) | clean |

The validator is genuinely strong. It pins skill frontmatter to one exact shape, syntax-checks every
shipped script, cross-checks plugin manifests against the `package.json` version, verifies the README

(175–953 characters, median 318) and only one pair collides. None of the 670 tracked Markdown files
has a broken relative link. That is unusually tidy for 46 plugins.

The items below are the gaps, worst first.

## 1. Two plugins ship the same skill, and the copies have drifted

**Severity: high — breaks skill selection.**

`11ai-security` and `11ai-audit` each hold one skill, and their descriptions are byte-for-byte
identical — all 553 characters. Only the skill names differ:

- `v0/plugins/11ai-audit/skills/11ai-audit-security-dependencies/SKILL.md` — 351 lines
- `v0/plugins/11ai-security/skills/11ai-security-dep-scan/SKILL.md` — 299 lines

The description is what an agent reads to decide which skill to run. When two descriptions match
exactly, nothing can pick between them — an agent will match both and choose arbitrarily. This is the
only duplicate pair among all 475 skills.

Git history says `11ai-audit` is the successor. It arrived in `bc5215c fix: init audit plugin`, while
`11ai-security` came from the much older `bec6c8c fix: refactor v0`. The audit version is the improved
one: it adds a `prepare_report_output.py` helper, timestamped run directories, collision handling, and
both Markdown and HTML reports. The security version still writes a single report straight into the
project root.

They have also diverged in code, not just prose. Both ship `scripts/scan_dependencies.py`, and the two
files now have different contents. A fix applied to one does not reach the other.

**To do**

- [ ] Decide whether `11ai-security` is retired or kept.
- [ ] If retired: delete `v0/plugins/11ai-security/`, drop its entry from
      `.claude-plugin/marketplace.json`, and remove its catalog row and layout entry from the root
      `README.md`. The validator enforces the counts, so it will confirm the removal is complete.
- [ ] If kept: rewrite both descriptions so each says plainly what makes it different, and reconcile
      the two copies of `scan_dependencies.py`.

## 2. Three benchmark skills tell the agent to run a script at the wrong path

**Severity: high — a documented command errors out.**

`verify-www-scope.mjs` lives at the plugin level, in `v0/plugins/11ai-benchmarks/scripts/`. Three
skills reference it as a bare `scripts/verify-www-scope.mjs`, which resolves inside the skill's own
folder, where the file does not exist:

- `v0/plugins/11ai-benchmarks/skills/11ai-benchmark-www/SKILL.md`, lines 35 and 209
- `v0/plugins/11ai-benchmarks/skills/11ai-benchmark-troubleshooter/SKILL.md`
- `v0/plugins/11ai-benchmarks/skills/11ai-benchmark-sync/SKILL.md`

Line 209 presents it as a literal command to run: `node scripts/verify-www-scope.mjs <tree-root>
<changed-path>...`. The agent will get a file-not-found error.

The same plugin already gets this right elsewhere — `../../scripts/hash-inputs.mjs` and
`../../scripts/account-transcripts.mjs` both use the two-level prefix — so the convention exists and
these four references simply missed it.

A related but softer case: the three automation-creator skills say to copy `scripts/run-tick.sh`
"from the core skill's" folder. The file does exist, at
`v0/plugins/11ai-agent-automation/skills/11ai-automation/scripts/run-tick.sh`. The prose carries the
meaning even though the bare path does not resolve.

**To do**

- [ ] Change all four references to `../../scripts/verify-www-scope.mjs`.
- [ ] Name the sibling skill explicitly in the three `run-tick.sh` references, so the agent does not
      have to guess where the core skill lives.
- [ ] Extend the validator to resolve inline `scripts/…` paths written inside backticks, not just
      Markdown link syntax. That is what let this class of error through.

## 3. A file holding your npm token is not ignored by Git

**Severity: high — credential exposure.**

`v0/scripts/publish-public-w-local-token.cjs` line 41 writes your npm token in plain text to
`.npmrc.codex-publish-temp` in the repository root. `.gitignore` does not cover it. The script deletes
the file afterward, but if you interrupt the publish with Ctrl-C the parent process dies before
reaching the cleanup, and the token file survives in your working tree — ready to be picked up by the
next `git add .`.

`v0/scripts/README.md` already knows about this and asks you to check by hand: "after an interrupted
publish, confirm that `.npmrc.codex-publish-temp` is gone because it contains the token and is not
ignored by Git." A manual step is a weak guard for a credential.

**To do**

- [ ] Add `.npmrc*` to `.gitignore`.
- [ ] Pass `{ mode: 0o600 }` to the `fs.writeFileSync` call so the file is owner-only while it exists.

## 4. Codex packaging is finished for 37 of 46 plugins

**Severity: medium — needs a decision, not just a fix.**

All 475 skills carry their `agents/openai.yaml` metadata. Only 37 plugins have a
`.codex-plugin/plugin.json`. Nine plugins have an empty `.codex-plugin/` directory — the folder was
created and the manifest never written:

`11ai-agent-automation`, `11ai-ai-chat`, `11ai-benchmarks`, `11ai-blog-builder`, `11ai-cleanup`,
`11ai-codebase`, `11ai-super`, `11ai-utils`, `11ai-xharness`

That is 79 skills — including the whole benchmarks and super suites — shipping Codex metadata inside a
plugin Codex cannot load. It reaches users: the published tarball contains 46 Claude manifests and only
37 Codex ones.

The validator says nothing because `v0/scripts/validate-skills.mjs` line 249 does
`if (!fs.existsSync(manifestFile)) continue` — a missing Codex manifest is skipped rather than
reported.

**To do**

- [ ] Decide whether Codex support is meant to be complete or deliberately partial.
- [ ] If complete: write the nine missing manifests and change that `continue` into a failure, so the
      gap cannot reappear.
- [ ] If partial: note the plugin-level gap in the root `README.md`, which currently says only "Every
      skill also includes Codex UI metadata in `agents/openai.yaml`".

## 5. The release workflow installs unpinned dependencies while holding your npm token

**Severity: medium — supply-chain surface on the publishing path.**

`.github/workflows/release.yml` runs `npm install`, and no `package-lock.json` is tracked at the
repository root. Your direct devDependencies are pinned to exact versions, which helps, but their
transitive dependencies resolve fresh on every release run. That job holds `NPM_TOKEN`,
`contents: write`, and `id-token: write`.

A compromised release deep in the semantic-release tree would therefore execute with permission to
publish as you. This is the risk the `11ai-audit` skill exists to catch, which makes it a conspicuous
gap in your own pipeline.

**To do**

- [ ] Commit a root `package-lock.json`.
- [ ] Switch the workflow's install step to `npm ci`.

## 6. Nothing in CI checks the website

**Severity: medium — no signal on a published surface.**

`v0/www` is 106 tracked files, and no workflow touches it. `validate-skills.yml` runs the skill
validator; `release.yml` runs it again and publishes. Neither runs the site's typecheck, lint, or
build.

This matters more than usual because the site reads all 475 skills at build time to generate 527 static
pages. A skill change the validator accepts but `v0/www/lib/skills.ts` chokes on breaks the published
site with no warning. All three commands pass today, so wiring them in costs nothing now and buys a
real signal later.

**To do**

- [ ] Add a website job to `.github/workflows/validate-skills.yml` running `npm ci`, `npm run
      typecheck`, `npm run lint`, and `npm run build` in `v0/www`.

## 7. Shared helper scripts are copied per skill with no drift check

**Severity: medium — the cause of finding 1, still unguarded.**

Two helpers are duplicated across the `11ai-llm-costs` skills:

- `pricing-history.mjs` — 4 copies
- `harness-support.mjs` — 3 copies

All copies are currently identical, which is the good outcome. Nothing enforces it — the validator
syntax-checks each file on its own and never compares them. Commit `01b1501` shows this is already
treated as a documented manual duty ("document cross-skill maintenance requirements in the plugin
README"). Finding 1 shows what happens when that duty slips: `scan_dependencies.py` has two copies
that no longer match.

**To do**

- [ ] In the validator, group shipped scripts by filename and fail when two copies of the same name
      have different hashes, unless the pair is on an explicit exception list.

## 8. Two small things

**A dead permission rule.** `.claude/settings.local.json` allows
`node 11ai/v0/11ai-llm-costs/skills/11ai-global-llm-cost/scripts/analyze-global-llm-cost.mjs`. Nothing
about that path is current: the directory is `v0/plugins/11ai-llm-costs`, the skill was renamed to
`11ai-llm-cost-global`, and the script to `analyze-llm-cost-global.mjs`. The rule can never match, so
you are prompted for a command you meant to allow.

- [ ] Update the rule to the current path, or drop it.

**A placeholder is the published entry point.** `v0/index.js` exports
`message: "Sample entry point for the 11ai package."` and is set as `main` in `package.json`. Anyone
who runs `require("@rj11io/11ai")` gets that string.

- [ ] Either make it return something useful — the plugin root path, or the catalog — or drop `main`
      and let the package be files-only.

## Where to start

Findings 1, 2, and 3 have real consequences: a skill pair no agent can choose between, a documented
command that errors out, and a token file one keystroke away from a commit.

Findings 4 and 5 are decisions more than bugs. You need to say whether Codex support is complete, and
whether the release job should install pinned dependencies.

Findings 6 and 7 are the same lesson twice. This project's quality rests almost entirely on one
validator script, so the cheapest durable win is teaching that script the two rules it does not yet
know: inline script paths, and copies that must stay in sync.
